# Система цифровой выдачи пропусков

MVP веб-приложения для бюро пропусков, работающего локально на моноблоке с
сенсорным экраном.

## Состав

- `backend/` — Node.js + Express + SQLite (better-sqlite3). Хранит справочники
  (управления, должности, сотрудники) и журнал посещений, генерирует QR-код и
  печатает чек на ESC/POS-принтере при регистрации.
- `frontend/` — React + Vite + Tailwind, интерфейс на русском языке,
  оптимизирован под touch-экран (крупные элементы управления).

## Быстрый старт

Требуется Node.js 18+.

```bash
# 1. Backend
cd backend
npm install
npm run dev      # http://localhost:3001

# 2. Frontend (в отдельном терминале)
cd frontend
npm install
npm run dev       # http://localhost:5173
```

Frontend в dev-режиме проксирует `/api` и `/uploads` на backend (см.
`frontend/vite.config.js`), так что достаточно открыть `http://localhost:5173`.

База данных SQLite создаётся автоматически в `backend/data/pass-system.db`
при первом запуске сервера, справочник управлений и должностей заполняется
стартовыми примерами (структура на основе МВД — редактируется в
«Справочниках»). Фото сохраняются в `backend/uploads/photos`.

## Экраны

- **Регистрация (`/`)** — форма выдачи пропуска на один экран без прокрутки:
  ФИО и ИИН посетителя (12 цифр), выбор управления → сотрудника (каскадный
  список), время регистрации (авто) и фото с веб-камеры (`getUserMedia`).
  При сохранении генерируется QR-код, печатается чек; если принтер
  недоступен, QR-код всё равно показывается на экране, а печать можно
  повторить кнопкой. Цифровая подпись посетителя не собирается — на чеке
  оставлено место для подписи сопровождающего сотрудника ручкой.
- **Журнал (`/journal`)** — список посещений с фильтрами по дате, сотруднику
  и поиском по ФИО или ИИН посетителя.
- **Справочники (`/admin`)** — CRUD для сотрудников, управлений/департаментов
  и должностей. Удаление — мягкое (`is_active = 0`), чтобы не ломать историю
  посещений.
- **Выход — без отдельного экрана.** Сканер QR работает на любой странице:
  приложение отличает скан от ручного ввода по скорости (сканер вводит весь
  код за миллисекунды), находит пропуск по `qr_code_value`, проставляет
  `checked_out_at` и показывает всплывающее сообщение поверх текущего экрана.
  Если в момент скана курсор стоял в поле ввода, символы кода из него
  убираются, а Enter сканера не отправляет форму. Повторный скан того же QR
  идемпотентен (показывает, что выход уже был отмечен).

## Чек посетителя

Перед пропуском на чеке печатается название учреждения (`INSTITUTION_NAME`
в `.env`, например «РОВД Алматинского района города Астаны»), затем: ФИО и
ИИН посетителя, дата/время регистрации, ФИО принимающего сотрудника, его
должность и управление, место для подписи сопровождающего сотрудника
(пустая строка — подпись ставится ручкой на бумаге) и QR-код (с
продублированным текстом кода) для сканирования на выходе.

## Учётные записи и доступ

Администратор один на все посты. Его вход задаётся в `backend/.env`
(`ADMIN_LOGIN`, `ADMIN_PASSWORD_HASH`), а не через интерфейс: на посту никто
не может создать себе права администратора.

- `npm run admin -- set-password` — задать пароль администратора: спросит его,
  запишет хеш в `backend/.env` и сразу применит.
- `npm run admin` — вывести строки `ADMIN_LOGIN` / `ADMIN_PASSWORD_HASH` с уже
  настроенного поста, чтобы вставить их в `.env` нового поста. Сам пароль
  нигде не хранится, только хеш (scrypt).

Новый пост: администратор входит, указывает учреждение (экран появляется сам,
пока название не задано), затем в «Справочники» → «Пользователи» добавляет
сотрудников. Вводится только ФИО и права, логин (`ivanov.ii`) и пароль
генерируются автоматически и показываются один раз. «Новый пароль»
выдаёт другой пароль и закрывает старые входы сотрудника; «Отключить» сразу
лишает доступа.

| Право         | Что открывает                                        |
|---------------|------------------------------------------------------|
| Регистрация   | экран регистрации, отметка выхода по скану (дежурный) |
| Журнал        | журнал посещений, фото, граф связей                  |
| Администратор | всё, включая справочники, учреждение и пользователей |

Права проверяет backend на каждом запросе, в том числе к фото (`/uploads`).
Вход — cookie `HttpOnly`; сессия закрывается после 12 часов бездействия.

## Настройка

Скопируйте `backend/.env.example` в `backend/.env` и укажите:

- `INSTITUTION_NAME` — название учреждения по умолчанию, печатается
  заголовком на чеке (например «РОВД Алматинского района города Астаны»,
  «ДП Астаны», «МВД РК»). Удобнее задавать его в интерфейсе: «Справочники» →
  «Учреждение». Сохранённое там значение хранится в базе этой установки,
  применяется к следующим чекам без перезапуска и имеет приоритет над `.env`.
- `PRINTER_INTERFACE`:
  - **USB-принтер, установленный в Windows** (обычный случай для моноблока):
    `printer:ИмяПринтера` — точное имя смотрите через `Get-Printer` в
    PowerShell или в «Устройства и принтеры». Печать идёт напрямую через
    спулер Windows (`winspool.drv`, вызывается из PowerShell) — никаких
    дополнительных npm-пакетов и нативной сборки не требуется.
  - **Сетевой принтер**: `tcp://IP:9100`.

Печать не блокирует регистрацию: при недоступности принтера пропуск всё
равно сохраняется, а QR-код можно показать на экране или напечатать позже
кнопкой «Повторить печать».

## Сканер QR/штрихкодов

Отдельного экрана «Выход» нет — сканировать можно в любой момент, на любом
экране. QR-код кодирует значение `qr_code_value` — 12 цифр: номер пропуска и
6 случайных цифр (например, `000012482913`; у старых пропусков —
`V12-3CDB5876`).

### Рекомендуемый режим: USB COM

Сканер переключается в режим **USB COM** (он же USB VCP / USB Serial /
«виртуальный COM-порт») сканированием служебного штрихкода из инструкции к
модели. В этом режиме сканер не вводит символы как клавиатура, поэтому не
мешает дежурному заполнять форму, даже если скан пришёлся на момент набора.

Backend сам читает порт (`backend/src/scanner/readSerialScanner.ps1`, через
.NET `System.IO.Ports` — без npm-пакетов и нативной сборки), отмечает выход и
рассылает результат открытым страницам через Server-Sent Events
(`GET /api/scanner/events`). Настройка в `backend/.env`:

- `SCANNER_PORT=auto` (по умолчанию) — найти COM-порт USB-устройства
  автоматически; Bluetooth-порты пропускаются. Если сканер отключён, backend
  ждёт его и подключается, как только он появится.
- `SCANNER_PORT=COM5` — конкретный порт («Диспетчер устройств» → «Порты
  (COM и LPT)»), если USB COM-устройств несколько.
- `SCANNER_PORT=off` — не читать порт.
- `SCANNER_BAUD_RATE` — скорость порта, обычно 9600.

Состояние сканера пишется в лог backend: «подключён к COM5» или «USB COM-порт
сканера не найден».

### Запасной режим: эмуляция клавиатуры

Если сканер оставлен в режиме клавиатуры, приложение слушает нажатия на уровне
окна и отличает скан от ручного ввода по скорости: очередь нажатий с паузами не
больше 50 мс, закончившаяся Enter (`SCAN_GAP_MS` в
`frontend/src/hooks/useGlobalQrScanner.js`). Символы кода убираются из поля,
где стоял курсор, а Enter сканера не отправляет форму. Ограничения: окно
браузера должно быть активным, а если дежурный нажмёт клавишу ровно во время
скана, код не распознается. Символы определяются по `event.code` (физическая
клавиша), чтобы русская раскладка не превращала латинские буквы кода в
кириллицу.
